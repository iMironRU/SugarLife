# Предложение к контракту моста: «неизвестно» для активного инсулина

Статус: **черновик, для обсуждения с ядром** (sugarlife-core / KMP-движок).
Связанное: `app/src/sources/bridge.ts` (`Monitor`), `app/src/sources/bridgeNightscout.ts`,
`app/src/domain/loopValue.ts`.

## Зачем

`Monitor` несёт три числа про инсулин:

```ts
confirmedIOB: number; assumedIOB: number; conservativeIOB: number;
```

Все три — `number`. Значения «неизвестно» среди них нет, а ноль означает совсем другое:
«инсулина на борту нет». Это разные вещи, и путать их в приложении, по которому человек
решает, колоть ли ещё, нельзя.

## Практический случай, который это ломает

Активный инсулин считает цикл, а не помпа. Помпа отчитывается сама по себе и чаще: резервуар,
батарея, статус. Поэтому штатно бывает состояние, где про помпу известно всё, а про инсулин на
борту — ничего: цикл на паузе, потерял связь с помпой, перезапускается, меняется резервуар.

Поймано на живых данных 11.08.2026. AAPS пишет в Nightscout документы двух сортов — полный от
цикла и короткий только от помпы. Два последних документа были короткими (`openaps: {}`), а
в предыдущем IOB 4,085:

```
07:12  openaps: {}      резервуар 75
07:07  openaps: {}      резервуар 75
07:00  iob 4.085        резервуар 56
```

Наш Nightscout-шим заполняет монитор так:

```ts
const iob = d?.iob ?? 0;
confirmedIOB: iob, assumedIOB: 0, conservativeIOB: iob,
```

То есть в этот момент мост сообщает `confirmedIOB: 0` — «подтверждено: инсулина ноль». Это
ровно та неправда, из-за которой можно уколоть лишнего.

В самой PWA мы это уже исправили: интерфейс показывает прочерк приглушённым цветом и причину
(«цикл молчит 30 мин»), разбор — `domain/loopValue.ts`, порог свежести 20 минут. Но через мост
наружу по-прежнему уходит ноль, потому что выразить «неизвестно» контрактом нечем.

## Что предлагается (аддитивно, старые мосты не ломаются)

```ts
export interface Monitor {
  // ...существующие поля...

  /** Когда ядро/цикл в последний раз считал IOB. null = не считал ни разу.
      Читатель сам решает, свежо ли (у PWA порог 20 минут). */
  iobAtMs?: number | null;
}
```

Почему так, а не `number | null` у трёх полей: это сломало бы всех, кто уже читает монитор,
а необязательное поле не ломает никого. Плюс время само по себе полезнее флага — по нему
можно сказать не только «неизвестно», но и «цикл молчит сорок минут», а это уже диагноз.

У нативного ядра это время заведомо есть: свой расчёт оно датирует. У Nightscout-шима тоже —
мы завели его внутри как `Device.loopAt` (время документа, в котором реально был `openaps.iob`).

## Что PWA делает до принятия

`Device.loopAt` считается локально в `app/src/sources/nightscout.ts` при сборке состояния помпы
из нескольких документов devicestatus. Как только поле появится в контракте, источником станет
снимок, а локальный расчёт останется только у шима.
