# Долги кода

Что стоит починить и почему — измеренное, а не по ощущению. Заведено 28 августа 2026.
Соседний файл `что-у-нас-есть.md` отвечает «это уже есть?»; этот — «что здесь не так».

## Сделано в этот заход

**Пятьдесят семь лишних экспортов убраны.** Компилятор разделил их точно, потому что
в проекте включён `noUnusedLocals`: снимаешь `export` — и он сам говорит, нужен ли
символ хоть кому-то.

- **сорок** оказались нужны только внутри своего файла: `export` расширял поверхность
  модуля без причины;
- **семнадцать** были мертвы совсем и удалены.

Осторожно с автоматикой: первая попытка удалить их скриптом снесла заодно три живые
функции по соседству — обход по балансу скобок ушёл дальше объявления. Поймал
компилятор, откатил, доделал руками. Мера здесь одна: `tsc` и тесты после каждого
шага, а не в конце.

## Хорошая новость, которую стоит записать

**Пороги по файлам не расползлись.** Проверка на повторяющиеся числа
(`15 * 60 * 1000` и подобные) в вебе и нативе нашла ровно одно место, и то внутри
одного файла. Правило «один ответ на один вопрос» на уровне констант держится —
после всего, что мы за август из-за него разгребали.

## Долг первый: девяносто шесть молчаливых `catch` в вебе

```
platform/appUpdate.ts     9      settings/storage.ts     5
platform/живойБаннер.ts   8      sources/nightscout.ts   4
platform/тревоги.ts       7      platform/фон.ts         4
```

Почти все — обёртки над нативом одной формы:

```ts
try { await Native.testAlarm(); return true; } catch { return false; }
```

Часть законна: метода нет в старой сборке, приложение живёт дальше. Но отличить
«метода нет» от «метод есть и упал» сегодня нельзя ниоткуда: следа не остаётся.

У натива для этого есть сторож (`scripts/молчаливые-отказы.sh`), у веба нет.

**Что предлагается:** один помощник, который зовёт натив и оставляет след — по
одной записи на имя метода за сеанс, чтобы не залить журнал. Плюс сторож,
требующий звать натив только через него.

**Почему не сделано сразу:** тридцать семь мест правятся механически, но каждое надо
прочесть — в половине отказ означает разное. Это работа на свежую голову, а не
двенадцатым делом за день.

## Долг второй: `решитьПоБаннеру` — сто пятьдесят одна строка

Самая длинная функция во всём нативе. Она же — место сегодняшней поломки: значок и
тихая сводка обновлялись внутри неё, и ранний выход унёс их вместе с карточкой
(#655). Разнесены (#658), сторож поставлен.

Сама функция осталась длинной: разбор снимка, расчёт числа, три порога, решение о
карточке. Разбирать её сейчас смысла мало — карточка выключена, и трогать
выключенное значит рисковать без выгоды. Вернуться, когда её будут включать
обратно, и разбирать вместе с переходом на push.

## Долг третий: `SugarLifeBridgePlugin.swift` — 1876 строк

Держит несоединимое: мост к движку, живую карточку, значок и сводку, проводку
тревог, журнал, выгрузку, BLE. Ровно из-за этого соседства и случилась поломка
значка: чтобы выключить одно, пришлось лезть туда, где живёт другое.

Разделение напрашивается по поверхностям, а не по строкам:

```
Мост          подписка на снимок, интенты, журнал
Поверхности   карточка, значок, сводка, виджет   ← у каждой свой файл
Тревоги       уже отдельно (Тревоги.swift)
BLE           уже отдельно
```

Это единственный долг, который окупится сразу: он убирает не строки, а соседство,
из-за которого правка одной поверхности задевает другую.

## Долг четвёртый: экраны — но не те, на которые думали

Строки оказались плохой мерой. Померили тем, что мешает читать на самом деле:
**сколько состояний надо держать в голове**. Признаки — ветвления в разметке, число
хуков, число изменяемых состояний, глубина вложенности.

```
файл                        строк  ветвлений  хуков  состояний  глубина
DeviceSection.tsx             700         67     13          7        8
LoopSetupSection.tsx          335         43      4          5       14
HeroPanel.tsx                 413         40     11          2        7
HealthSection.tsx             315         38      5          9        6
FoodSheet.tsx                 422         37     14         12       11
Today.tsx                     669         35     22          7        6
BasalProfileSection.tsx       298         19      6          9       15
```

**`DeviceSection` — единственный явный выброс.** Шестьдесят семь ветвлений, почти
вдвое больше следующего. Читая её, невозможно удержать, какой из четырёх приборов ты
сейчас смотришь. Это чинится не разбиением на файлы, а выносом каждого вида прибора в
свой компонент — тогда держать в голове будет нечего. Задача #406, половина сделана:
чистые помощники уже вынесены и покрыты тестами.

**`Today` — НЕ долг, хотя второй по длине.** Тридцать пять ветвлений и глубина шесть:
экран длинный, но плоский. Его длина — содержание, а не сложность. Резать его значит
менять читаемый текст на прыжки между файлами.

**`BasalProfileSection` и `LoopSetupSection` — глубина 15 и 14 при трёх сотнях строк.**
По строкам они не видны вовсе, а читаются тяжелее семисот строк `Today`. Внутри —
логика, живущая в разметке:

```tsx
<button onClick={() => {
  const idx = new Set(segsIn(work, p).map((x) => x.i));
  apply(work.map((s, i) => (idx.has(i) ? { ...s, v: roundRate(s.v * (1 + d / 100)) } : s)));
}}>
```

Расчёт внутри обработчика внутри `.map()` внутри условия внутри разметки. Лечится
выносом расчёта в чистую функцию рядом — её заодно можно проверить тестом, а сейчас
нельзя никак.

Признак редкий: обработчиков с логикой больше одной инструкции нашлось всего в трёх
файлах. То есть это не привычка, а три места.

## Чем меряли

```sh
V=$(grep -oE "\{[^}]*&&|\?[^:]*:" "$f" | wc -l)          # ветвления в разметке
H=$(grep -cE "use[A-ZА-Я][A-Za-zА-Яа-я]*\(" "$f")         # хуки
S=$(grep -cE "useState|useRef|useReducer" "$f")           # изменяемые состояния
D=$(awk '{n=gsub(/[({[]/,"");m=gsub(/[)}\]]/,"");d+=n-m; if(d>mx)mx=d} END{print mx}' "$f")
```

Мера грубая и специально такая: она не заменяет чтение, а показывает, что читать
первым. Строки этого не показывали — по ним `Today` выглядел вторым долгом, а
`BasalProfileSection` не выглядел долгом вовсе.
