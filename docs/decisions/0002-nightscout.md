# 0002. Наполнение приложения данными из Nightscout

Статус: принято (срез 1 — глюкоза)
Дата: 2026-07-29

## Контекст

Приложению нужны реальные данные вместо демо-наборов. У пользователя есть
Nightscout (self-hosted, AndroidAPS + помпа Medtronic, замкнутая петля).

Проверка живого инстанса из браузера (origin `imiron.ru` → домен Nightscout)
показала: **CORS включён, роль `readable` по умолчанию — читается без токена**.
Значит статичный PWA на Pages может ходить в Nightscout напрямую, без бэкенда.

## Решение

**Транспорт:** прямой `fetch` из браузера. Без прокси/бэкенда — соответствует
принципу «локально, без облака». Конфиг (URL + опц. токен) — только в `localStorage`.

**Модель данных → экраны** (что реально отдаёт инстанс):
- `entries` (SGV, mg/dl) → круг глюкозы, стрелка тренда (`direction`), «N мин назад»,
  список измерений, кривая на графике. Конвертация mg/dl → ммоль (÷18) на входе.
- `treatments` → болюсы/углеводы/temp basal, дата Sensor Start (день сенсора).
- `devicestatus` → IOB/COB, резервуар, статус помпы, базал.
- `profile` → СУИ/ISF/базал/target для калькулятора болюса.
- Единицы и пороги — **источник истины: настройки приложения**, не Nightscout.

**MVP — только чтение.** Действия (болюс, еда, ручной ввод) пока локальные,
обратно в Nightscout не пишем.

**Архитектура:**
- `nightscout.js` — адаптер (fetch + нормализация + `ping` для проверки).
- `store.js` — стор: поллинг 60 c, кэш в `localStorage`, офлайн; при отсутствии
  конфига данных нет → `renderVals` берёт демо-наборы (fallback).
- `renderVals()` читает из стора живые значения, иначе демо.
- Service worker: Nightscout-запросы **не кэшируются** (иначе заморозятся данные);
  кэш-first только для CDN шрифтов/иконок.

**Конфиг-UX:** шторка «Nightscout» (Профиль → Nightscout): URL, токен, «Проверить и
подключить», тумблер синхронизации, статус и «обновлено N мин назад».

## Что сделано в срезе 1

Живые: значение сахара в круге, стрелка тренда, «N мин назад», строка синхронизации,
список последних измерений, кривая глюкозы на графике шторки. Проверено на реальном
инстансе (сахар ~13–14 ммоль) и в демо-режиме (fallback).

## Дальше (следующие срезы)
- Помпа/IOB/резервуар/статус из `devicestatus`; калькулятор болюса из `profile`.
- Столбики углеводов/инсулина на графике из `treatments`; счётчик дня сенсора.
- Метрики (TIR/среднее/SD) — расчёт на клиенте из entries за период.
- Авто-масштаб оси Y графика (сейчас фиксированная 4–12 ммоль, сахар выше пегается у края).
- Живые метки времени на оси X (сейчас статичные).
- Realtime по Socket.IO вместо поллинга (опционально).

## Приватность
Персональный URL/токен пользователя **не в коде** — вводятся в приложении, хранятся
только на устройстве. В репозитории демо-данные и пустой конфиг по умолчанию.
