# 0004. Управление подачей — отдельная про-редакция; интерфейс строим первым

Статус: принято
Дата: 2026-08-09

## Контекст

В концепции и `CLAUDE.md` зафиксировано правило №1: **только чтение, никаких команд
доставки инсулина**. Получен комплект по петле (`inbox/loop.zip`): единая модель, шкала
полномочий L0…L4, шесть классов ограничений, модель времени, ролевая модель, два
прототипа — рабочие экраны и мастер первичной настройки.

Комплект прямо противоречит правилу №1, если читать его буквально. Значит противоречие
надо снять явным решением, а не молча начать писать код.

## Решение

**Управление подачей живёт в отдельной про-редакции.** Линия раздела — ролевая, и она
совпадает с регуляторной:

| редакция | содержимое | канал раздачи |
|---|---|---|
| лайт | всё, что не касается ввода инсулина | магазины приложений |
| про | управление подачей, петля | самосборка либо TestFlight |

Наблюдатель (родитель, врач) никогда не вводит инсулин — значит наблюдательская часть по
определению чистая и целиком помещается в лайт. Правило №1 остаётся в силе для лайта
без изменений.

**Строим сначала интерфейс, при уровне полномочий L0.** L0 — не заглушка, а штатный режим
из модели: «команды не отправляются, помпа работает по своему профилю». Интерфейс
показывает, какое решение петля приняла бы и какие ограничения его срезали, но ничего не
отправляет.

## Почему так

Прежде чем разрешать алгоритму что-то отправлять, надо неделями смотреть, как он себя
ведёт на настоящих данных. Интерфейс ограничений и лестница полномочий проверяются
полностью в L0 — на живом Nightscout, с нулевым риском.

Технически отправлять и нечем: мост read-only, движок — скелет, пути записи в помпу не
существует. То есть это решение сейчас ничего не разблокирует, а только фиксирует рамку.

## Следствия

- Мастер настройки, профиль ограничений и индикатор уровня — обычный локальный конфиг,
  подачи не касаются. Делаем в ветке `claude/connect-ux-preview`.
- Переход с L0 на любой уровень выше требует отдельного решения и отдельной записи в этом
  журнале. Само наличие в интерфейсе выбора режима таким решением НЕ является.
- Правило №1 в `CLAUDE.md` продолжает действовать для лайт-редакции. При появлении
  реальной про-сборки его формулировку надо будет уточнить со ссылкой на это решение.
- Разделение по App ID (наблюдательское приложение отдельно) — отдельная задача, всплывёт
  при раздаче, не сейчас.
