# Устройство исходников

Папка отвечает на вопрос «что это такое», а не «какого оно типа». Раньше было
наоборот — `data/` и `components/` собирали в кучу всё подряд, и по имени папки
нельзя было понять ни что внутри, ни куда класть новое.

```
app/        оболочка и её состояние: App, верхняя панель, карусель вкладок,
            жест сворачивания, стек страниц
screens/    вкладки: Сегодня · Метрики · НМГ · Инсулин · Профиль + онбординг, лоадер
sections/   страницы стека — то, что открывается поверх вкладки:
            Устройства, Сервисы, карточки устройства и облака, базальный профиль, петля
sheets/     шторки: одноразовые подзадачи (выбор модели, сканирование, единицы)
ui/         кирпичи интерфейса: Row, PageHead, HoldButton, NotConfigured
charts/     графики и общий доступ к CSS-переменным
domain/     предметная логика без побочных эффектов: расчёт базала, показатели
            гликемии, статистика расходников, справочники, единицы, типы
sources/    откуда берутся данные: Nightscout, сокет, мост, локальная БД, стор
settings/   что человек настроил на этом устройстве: реестр устройств, профиль
            петли, флаг онбординга, сброс
platform/   возможности платформы: обновления, уведомления, выгрузка файлов
theme/      стили, разложенные по областям (см. theme/app.css — точка сборки)
```

## Правила, которые держат это в форме

**Зависимости идут только вверх, к интерфейсу.** `domain/`, `sources/`, `settings/`
и `platform/` ничего не знают про экраны. Это не договорённость на словах: правило
`no-restricted-imports` в `.oxlintrc.json` уронит сборку при попытке импортировать
`@/ui/...` из домена.

**Типы предметной области живут в `domain/types.ts`, а не в адаптере.** `Entry`,
`Treatment`, `Device`, `Profile` описывают диабет, а не протокол Nightscout.
Появится прямое чтение по BLE — типы останутся прежними, поменяется только адаптер.

**Импорты через `@/`.** Относительные пути привязывают файл к его нынешнему месту
и переписываются пачками при любом переезде.

**Страница или шторка?** Если у экрана есть родитель, к которому возвращаются, —
это страница стека (`sections/`). Если это одноразовая подзадача, прерывающая
поток, — шторка (`sheets/`). Отсюда и разные значки: страницу проходят назад
стрелкой, шторку закрывают крестиком.

## Проверка

```
npm test    типы тестов + vitest: домен покрыт тестами, включая расчёт доз
npm run build   tsc -b + vite
npm run lint    oxlint, включая правило слоёв
```

Тесты домена — не формальность: это единственное место, где считаются дозы
инсулина. `settings/reset.test.ts` дополнительно сверяет список очищаемых ключей
хранилища с тем, что реально встречается в коде, — этот список отставал трижды.
